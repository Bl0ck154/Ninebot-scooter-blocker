# Capturing authentic app screenshots

The main README currently includes an **illustrative UI preview** with example numbers. It is not a live device capture. Replace or supplement this preview with authentic screenshots from the latest released Android build.

## Capture checklist

1. On a **Ninebot Max G30 you own**, pair and authenticate with the latest official app release.
2. Capture the **Dashboard** while connected: model name, connection status, battery, speed/session and the large software lock button.
3. Capture the **Statistics** view with the activity calendar and day/week/month summary. Use real historical rides or an obviously empty history; do not manufacture rides and present them as real.
4. Optionally capture an expanded **persistent notification** showing the lock action and ride data.
5. Use a consistent portrait crop and readable resolution. Prefer PNG. Remove or blur serial numbers, Bluetooth MAC addresses, personally identifying notifications and sensitive activity/location information.
6. Save files as `docs/assets/dashboard.png`, `docs/assets/statistics.png` and optionally `docs/assets/notification.png`. Add meaningful alt text, then replace the illustrative preview in README with the authentic images.
7. Verify screenshots still match the currently released APK before publishing. If any composite/mockup is included, label it as an illustration rather than a device screenshot.

Do not imply that BLE software lock prevents carrying a scooter away or that any model other than the hardware-tested G30 is verified.
